1. Introducción a la Programación y Tipos de Lenguajes
Software: Conjunto de programas e instrucciones que ejecutan tareas en un ordenador.

Programa: Secuencia de instrucciones entendibles por el ordenador, con un objetivo concreto.

Lenguajes de programación:

Bajo nivel: Cercanos al código máquina, difíciles de programar (ej: lenguaje máquina).

Alto nivel: Más cercanos al lenguaje natural, necesitan traducción (ej: C, Java, PHP, Python).

Modelos de ejecución:

Compilados: Mayor rendimiento, específicos para una plataforma (ej: C, Go).

Interpretados: Más fáciles de programar, requieren un intérprete (ej: PHP, Python).

Intermedios: Compilados a un lenguaje intermedio y ejecutados en una máquina virtual (ej: Java, Scala).

2. Aplicaciones Web y Móviles
Frontend: Parte cliente (navegador), usa HTML, CSS, JavaScript.

Backend: Parte servidor, maneja lógica, bases de datos y APIs (ej: PHP, Java, Python).

APIs: Permiten comunicación entre sistemas mediante HTTP, usando formatos como JSON o XML.

Seguridad:

Amenazas comunes: Inyección SQL, XSS, CSRF, robo de sesión.

Desafíos: Diversidad de dispositivos, gestión de contraseñas, actualizaciones frecuentes.

3. Elementos Básicos de un Programa
Componentes clave:

Variables, estructuras de control, funciones, manejo de errores.

Comentarios (evitar información sensible).

Entornos de Desarrollo (IDE):

Herramientas como Visual Studio Code, IntelliJ IDEA.

Funciones: editor de código, depuración, gestión de proyectos, análisis estático.

Librerías y Frameworks:

Librerías: Conjunto de funciones reutilizables.

Frameworks: Estructura predefinida para desarrollo.

4. Pruebas de Software
Clasificación por visibilidad del código:

Caja blanca: Acceso total al código.

Caja negra: Sin acceso al código.

Caja gris: Conocimiento parcial.

Tipos de pruebas:

Unitarias, integración, funcionales, aceptación, usabilidad, rendimiento, regresión, seguridad.

Pruebas de seguridad:

Análisis estático y dinámico, penetración, vulnerabilidad, seguridad web/móvil/APIs.

Herramientas:

SonarQube, Burp Suite, OWASP ZAP, Selenium, Metasploit.

5. Evaluación de Lenguajes de Programación
Seguridad:

No depende solo del lenguaje, sino del programador, tecnología y volumen de código.

Ejemplo: C tiene muchas vulnerabilidades debido a su antigüedad y amplio uso.

Buenas prácticas:

Guías como OWASP Secure Coding Practices.

Entornos controlados:

Sandbox: Entorno aislado para pruebas sin afectar producción.

6. Recomendaciones para Pruebas
Definir casos de prueba con entradas válidas y no válidas.

Evitar que el programador pruebe su propio código.

Automatizar pruebas para eficiencia.

Documentar todos los casos de prueba.

Conclusión
La elección del lenguaje depende de los requisitos del proyecto.

La seguridad debe integrarse en todas las fases del desarrollo.

Las pruebas automatizadas y el uso de sandboxes son esenciales para garantizar la calidad y seguridad del software.
